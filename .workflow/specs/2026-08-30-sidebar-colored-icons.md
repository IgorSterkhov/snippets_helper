# Цветные контурные иконки сайдбара

## Контекст

Основное desktop-приложение использует компактный вертикальный сайдбар шириной 48 px. Значки Finance, DEV, SQL и Superset сейчас выглядят монохромными и хуже различаются, чем существующие emoji-иконки Shortcuts, Notes и Tasks.

Пользователь выбрал визуальное направление **B1 Clean color**: цветные контурные SVG без плиток, рамок, фоновых заливок и свечения.

## Цель

Сделать четыре проблемных значка цветными и визуально согласованными с текущим компактным сайдбаром, не меняя структуру навигации, размеры кнопок и способ выделения активного раздела.

## Утверждённое визуальное направление

Предмет интерфейса — утилитарное desktop-приложение для быстрого доступа к рабочим данным и инструментам. Аудитория — опытный пользователь, которому важнее мгновенное распознавание модуля, чем декоративность. Единственная задача изменения — ускорить различение Finance, DEV, SQL и Superset.

### Цветовые токены

- Finance green: `#56d364`.
- DEV violet: `#bc8cff`.
- SQL blue: `#58a6ff`.
- Superset coral: `#ff7b54`.
- Existing muted label: `#8b949e`; цвет подписей не меняется.

### Типографика и компоновка

Типографика, подписи размером 8–9 px, кнопки 48×48 px и ширина сайдбара остаются без изменений.

```text
┌────────┐
│  🏷️   │ Shortcuts
│  🗒️   │ Notes
│  ✅   │ Tasks
│  $    │ Finance   ← зелёный контур
│ </>   │ DEV       ← фиолетовый контур
│  DB   │ SQL       ← синий контур
│  ∞    │ Superset  ← коралловый бренд-знак
└────────┘
```

### Характерный элемент

Каждый из четырёх модулей получает собственный постоянный цвет, но форма значка остаётся лёгкой и не создаёт нового контейнера внутри кнопки.

### Самопроверка направления

Вариант с цветными плитками добавлял второй визуальный слой, которого нет у остальных значков. В B1 эта декоративная сущность убрана: различение создаётся только формой и цветом самого глифа. Новая анимация, свечение и дополнительная рамка не нужны.

## Функциональные требования

1. Finance отображается контурным знаком валюты цветом `#56d364`.
2. Группа DEV отображается контурным знаком кода цветом `#bc8cff`.
3. SQL отображается контурным знаком базы данных цветом `#58a6ff`.
4. Superset отображается существующим бренд-знаком Apache Superset цветом `#ff7b54`.
5. Векторные значки не имеют плитки, рамки, скруглённого контейнера, тени или свечения.
6. Активная кнопка сохраняет существующий фон `var(--bg-secondary)` и левую полосу `var(--accent)`.
7. Существующие emoji-значки и подписи остальных модулей не меняются.
8. Значки в истории просмотров и других несайдбарных потребителях сохраняют прежние строковые значения.
9. Изменение остаётся frontend-only: Rust, Tauri-команды и IPC-сигнатуры не меняются.

## Доступность

- Название модуля остаётся текстом под значком, поэтому цвет не является единственным способом распознавания.
- Кнопки, `data-tab-id`, `data-group-id`, состояния `active`, `expanded` и `has-active-child` не меняются.
- Контраст цветов рассчитан для существующего фона `#1c2128`.

## Проверка

- CDP smoke-тест раскрывает DEV и проверяет реальные видимые DOM-элементы и computed styles четырёх значков.
- Тест загружает каждый SVG-ресурс, проверяет ненулевой размер глифа, opacity/visibility, SVG mask, ожидаемый цвет заливки маски, отсутствие контейнерной рамки/скругления/свечения и сохранение штатного active-state.
- После активации SQL группа DEV остаётся раскрытой, получает `has-active-child`, но не получает `.active`; Finance сохраняет свой зелёный цвет после активации.
- История просмотров продолжает получать исходные `$`, `🗃` и `logo:apachesuperset`, а не sidebar-only `outline:` значения.
- Существующий ClickHouse logo остаётся размером 1em и не наследует новую фиксированную геометрию outline-иконок.
- `node --check` запускается для изменённых JS-файлов.
- Полный `python3 dev-test.py` должен завершиться без ошибок.

## Релиз

Само изменение не меняет IPC, но релизный канал нельзя определять только по diff этой задачи. Текущая `main` после `v1.24.2` уже содержит unreleased изменения в `desktop-rust/src-tauri/`, а recovery-тег `f-20260830-1` находится на боковой ветке и не является предком `main`. Перед релизом нужно проверить полный diff от последней опубликованной native-базы и ancestry recovery-тега. Релиз из `main`, вероятно, потребует patch `v*`; frontend-only тег допустим только на отдельно подтверждённой безопасной frontend-линии. Из-за несвязанных dirty-файлов commit/tag/push требуют отдельного подтверждения пользователя.
